# 먹 스플랫 엔진

Quest 3S에서 손끝 좌표를 받아 그림을 그리는 데에는 WebXR Hand Input과 WebGL 2면 충분하다. 기존 Unity 프로젝트의 입자 운동식을 JavaScript로, 스플랫의 광학적 감쇠를 GLSL ES로 옮겼다. 런타임에는 게임 엔진, 모델 파일, 동영상, 외부 텍스처 요청이 없다.

## 먹의 농담

한 붓은 거리 12mm마다 붓털 묶음을 찍는다. 중심에는 안료를 많이 두고 양쪽 가는 털에는 안료를 덜 싣는다. 진행 거리와 속도가 농도, 물기, 갈필의 틈을 바꾼다. 정지한 붓끝의 떨림은 거리 임계값 안에서 획을 반복해 덧칠하지 않는다.

각 스플랫은 중심 위치, 장축 방향, 두 반경, 안료량, 초기 물기, 색, 고정된 종이결 시드, 생성 시각을 저장한다. 나이가 들수록 획에 수직으로 젖은 폭이 넓어지고 옅어진다. 가장자리에는 물기가 빠지며 남는 얇은 침전 띠를 더한다. 픽셀의 안료 농도를 `D`라고 하면 피복률은 `1 − exp(−D)`다. 같은 색을 거듭 그은 자리의 투과율은 각 획의 투과율을 곱한 값이다. 먹을 맑게 풀거나 겹쳐 칠하는 차이를 이 방식으로 낸다. 수분의 이동은 각 스플랫에서 해석적으로 근사한다.

## 손 궤적에서 소환까지

1. 검지만 펴거나 핀치한 쪽 손을 획의 주인으로 고정한다. 샘플로부터 면적 벡터를 계산해 그린 평면을 찾는다. 평면에서 감긴 각도, 되감기, 종횡비, 끝점 거리, 깊이 오차로 원을 판정한다. 약간 찌그러진 원과 양방향을 받는다.
2. 원을 알아보면 자리에 고정한다. 약 1.1초 동안 테두리의 안료가 안쪽으로 모인다. 손바닥은 손목과 너클에서 계산한다. 세 손가락 이상을 펴고, 손바닥이 진을 향하며 중심부에 머물러야 기운이 차오른다.
3. 중심의 烏는 직접 정의한 열 개의 획에서 샘플링한다. 주입이 끝나면 2,370개 입자의 목표를 글자에서 새의 몸통, 부리, 꼬리, 좌우 날개깃으로 바꾼다. 진에는 옅은 먹 자국이 남는다. 새는 한 번 펼쳐 보인 뒤 상대를 추적한다.
4. 까마귀가 적에게 접근하면 피해를 한 번 적용한다. 상대는 조준 예고 후 직전 머리 위치를 겨눈다. 두 공격, 피격 먹방울, 잔상, 손의 기류 모두 같은 스플랫 버퍼 형식을 사용한다.

## 렌더링과 기기 확인

한 XR 프레임에 시뮬레이션을 한 번 수행하고 버퍼를 업로드한 다음 두 눈의 뷰로 각각 그린다. 풍경은 한 번만 올린다. 패스스루에서는 가상 풍경과 종이 배경을 건너뛴다. 72Hz를 지원하는 세션에는 72Hz를 요청하고, 눈별 렌더 해상도 배율을 0.86으로 둔다. 프레임 표시 값은 XR 콜백 사이의 실제 간격이다.

데스크톱에서는 WebGL 2를 우선 사용한다. 이를 쓸 수 없는 브라우저에서는 같은 입자 버퍼를 Canvas 2D로 투영한다. XR 입장에는 WebGL 2가 필요하다. 실기에서 남은 확인 항목은 [검수 메모](../review/README.md)에 있다.
