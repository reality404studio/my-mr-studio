## 1. 한 줄 컨셉

**출퇴근길에 넋 놓고 바라본 빛과 재질을 손가락 사이로 물감처럼 담아 오고, 집에 와서 손끝으로 아무 오브제에나 "푝" 찍어 바른다.**

태그라인 초안 (140자 제한):
> Gaze at the light on your commute, catch it between your fingers, dab it onto anything at home.

### 왜 이게 이기는 자리인가
- **폰 컬러 피커(Adobe Capture 등)와의 차별점**
  1. 폰을 꺼내 겨누지 않는다 → 흔들리고 밀리는 전철에서도 채집이 된다.
  2. **움직이는 재질을 담는다.** 한강 물결 같은 움직임을 짧은 반복 루프 텍스처로 떠 온다. 멈춘 색만 따는 기존 앱과 다르다.
  3. **빛 방향까지 담는다.** 셀 셰이딩은 밝은 톤, 그림자 톤, 빛 방향 하나로 굴러가므로, 채집 순간의 빛이 그대로 오브제의 그림자 방향이 된다.
- **스타일 서명:** 현실 재질이 **90년대 셀 애니 재질**(2톤 셀 셰이딩, 남색 외곽선)로 변환된다. 90년대 셀 애니의 물 반짝임은 원래 짧은 루프 작화라서 물결 루프와 스타일이 정확히 맞물린다.
- **재사용:** 만든 오브제와 재질을 게임 에셋(GLB + 스프라이트 시트)으로 내보낸다. 사용자의 원래 바람("나중에 게임에서 쓸 수 있으면")이다.

## 4. 핵심 경험 설계

### 4-1. Gaze — 응시 (전철)
- 눈(Quest 3에서는 **머리 방향 레이로 대체**)이 채집 중심을 정한다.
- **오래 볼수록 물감이 진해진다.** 3초는 옅게, 20초 넋 놓고 보면 깊게 우러난다.
- **응시 시간 = 루프 길이.** 오래 본 만큼 움직임이 길게 담긴다.
- 의도: 피곤한 퇴근길의 멍한 응시를 채집 행위로 바꾼다. 응시를 클릭 대용(오래 보면 눌림)으로 쓰지 않는다.

### 4-2. Catch — 담기 (전철)
- **전철에서는 팔을 뻗지 않는다.** 레이캐스트 겨누기나 두 손 프레임은 전철에서 쓰지 않는다.
- 무릎 위 한 손으로 **엄지-검지 간격을 벌리면 채집 원이 커지고, 좁히면 작아진다.**
- **손가락을 붙이면 담긴다.**
- 정밀 선택은 집에서 한다(4-4). 막 찍고 나중에 크롭하는 사진 습관과 같다.

### 4-3. 팔레트 포탈 — 왼손바닥 (전철·집 공통)
- **왼손바닥을 위로 뒤집으면 포탈이 열리고**, 그 안에 오늘 모은 물감들이 떠 있다.
- **오른손가락을 포탈 안에 쑥 넣었다 빼면 손끝에 물감이 묻어 나온다.** "메뉴 선택 → 확인 → 칠하기"가 "찍어 바르기" 한 동작으로 줄어든다. 화가가 왼손에 팔레트를 드는 관습을 빌렸다.
- 구현 주의:
  - 포탈을 **손바닥 위 5~10cm에 띄운다.** 두 손이 맞닿으면 손 추적이 흔들린다.
  - **Quest 시스템 제스처와 충돌:** 손바닥을 내 쪽으로 향한 채 엄지-검지를 붙이면 시스템 메뉴가 열린다. 포탈이 열린 상태에서는 집기 동작을 쓰지 말고 "넣었다 빼기"만 쓴다.

### 4-4. 다듬기 (집)
- 모은 물감을 꺼내 범위를 다시 자르고, 루프 구간을 고르고, 셀 톤을 조정한다.
- 집에서는 레이캐스트, 두 손 프레임 등 큰 동작을 써도 된다.

### 4-5. Dab — 푝 (집)
- 기본 스컬프 오브제(우선 **페트병, 의자, 머그** 3종)를 손끝으로 찌르면 **닿은 지점부터 재질이 번져 나간다.**
- 손 판단: 살짝 톡 찍으면 얇게, 꾹 누르면 두껍게 칠한다 (접근 속도, 관통 깊이, 손가락 굽힘).
- 채집한 빛 방향이 오브제의 셀 그림자 방향이 된다. 예: "퇴근길 한강 노을빛"을 바르면 그때 그 방향으로 그림자가 진다.

### 4-6. 내보내기
- GLB(메시 + 정지 텍스처) + 루프 스프라이트 시트 PNG + 셰이더 파라미터 JSON.
- glTF에는 애니메이션 텍스처 표준이 없으므로, 루프는 스프라이트 시트와 메타데이터로 따로 내보낸다.

### 데모 영상 첫 20초 (콘티 초안)
퇴근길 전철 → 한강 철교 위 노을 물결을 넋 놓고 응시 → 손가락 사이로 담김 → 집 책상 → 왼손바닥 포탈에서 물감 묻히기 → 페트병에 "푝" → 병 표면에 셀 애니 물결이 흐름.

## 5. 기술 계획 (Unity, Quest 3)

### 스택
- Unity + **Meta XR SDK All-in-One** (대회 권장 v81+)
- **Passthrough Camera API** (Quest 3/3S, 헤드셋 카메라 권한 필요, Meta 문서 확인)
- 손 추적: Meta XR Interaction SDK
- 눈 추적(글래스용, 선택): Meta 눈 추적 컴포넌트. 없으면 머리 레이로 대체.
- (선택) **Unity Inference Engine(구 Sentis)**: 손 판단용 소형 ONNX 분류기
- 내보내기: glTFast export

### 모듈
| 모듈 | 내용 | 메모 |
|---|---|---|
| `Capture` | 응시 중심 + 채집 원 → 카메라 프레임에서 해당 영역 크롭 | 카메라 자세와 내부 파라미터로 월드 좌표를 이미지 좌표로 투영한다. **원본 전체 프레임은 저장하지 않는다.** |
| `CelExtract` | 크롭 영역에서 밝은 톤/그림자 톤 2~3색 추출 (k-means 등), 밝은 쪽 방향으로 빛 방향 근사 | 디라이팅을 하지 않는다. 밝은 면 = 셀 밝은 톤, 어두운 면 = 셀 그림자 톤으로 그대로 쓴다. |
| `LoopCapture` | 약 2초, 10~15fps 프레임 수집 → 끝과 시작을 크로스페이드해 반복 루프 → 플립북/텍스처 배열 | 물결은 무작위 패턴이라 전철이 움직여도 텍스처로 성립한다. 셀 단순화가 흔들림과 저화질을 덮어준다. |
| `PaintStore` | 물감 저장/로드 | 아래 데이터 구조 참고 |
| `PalettePortal` | 왼손바닥 뒤집기 감지 → 포탈 UI → 오른손 진입/이탈 감지 → 손끝에 물감 부착 | §4-3 주의사항 |
| `DabPaint` | 손끝 접촉점 → 오브제별 페인트 마스크(렌더 텍스처)에 번짐 기록 | 접촉점으로부터의 거리 + 노이즈로 번지는 연출 |
| `CelShader` | 트라이플래너 매핑(UV 불필요) + 셀 램프(밝은 톤/그림자 톤/빛 방향) + 남색 외곽선 + 플립북 재생 | 어떤 스컬프에도 UV 걱정 없이 바른다. |
| `HandJudge` | 톡/꾹 판별, 핀치 간격 → 반경 | **1차는 휴리스틱**(속도, 깊이). ML 분류기는 여유 있을 때. |
| `Export` | GLB + 스프라이트 시트 + JSON | |

| 11-10 ~ 11-12 | **Dab:** 왼손 팔레트 포탈, 손끝 물감 묻히기, 번짐 페인트 마스크, 트라이플래너 셀 셰이더, 오브제 3종 |
| 11-13 ~ 11-14 | 내보내기(GLB + 스프라이트 시트 + JSON), 저장/재개, 빠른 시작 |
| 11-15 | 폴리시: 첫 5분 온보딩, 사운드, 셀 외곽선 정리. (가능하면) 눈 추적 층 |
| 11-16 ~ 11-17 | **데모 영상** 편집(3분 미만, 첫 20초 콘티), 제출 폼 초안, 핸즈 온리 완주 테스트 |
| 11-18 | APK를 "Competition" 채널에 업로드, 초대 URL 확인, **저녁까지 제출** |

**MVP 선 (이것만 되면 제출 가능):** 머리 레이 + 핀치로 채집 → 정지 텍스처 + 2톤 + 빛 방향 → 왼손 포탈 → 페트병 하나에 "푝" 번짐 → 셀 셰이더 표시. 루프 텍스처는 MVP 바로 다음 우선순위다(차별점의 핵심).

## 8. 열린 결정 (사용자가 정한다 — Claude Code가 혼자 정하지 말 것)

1. **이름:** `Gaze · Catch · Dab`을 제안했다. 사용자의 원안은 `gaze-catch-get`이었고, 아직 확정하지 않았다. (Get은 Catch와 의미가 겹친다는 게 제안 이유)
2. **CRT 데스크 세계를 남길지:** 집 쪽 무대를 기존 로파이 CRT 데스크(CRT에서 물건이 넘어오는 세계)로 둘지, 셀 애니 스타일만 가져오고 세계관은 뺄지.
3. **트랙:** Productivity(크리에이티브 툴) vs Entertainment.
4. **부문:** New Experience vs Adapted. 2026-09-24 이전 코드나 빌드가 있는지 확인이 필요하다. (아트디렉션 문서는 10-13 작성)
5. **손 판단:** 휴리스틱만 쓸지, 소형 ML 분류기까지 넣을지.
6. **기본 오브제 목록:** 페트병, 의자, 머그로 충분한지.

## 9. 사용자와 일하는 방식

- 사용자는 **방향을 정하고 검수하는 역할**이다. 코드는 Claude Code가 쓰되, 각 단계에서 무엇을 만들었는지, 어떻게 확인할 수 있는지 짧게 보고한다.
- **창작 결정은 넘긴다.** 사용자는 "베이스라인 차분" 방식을 쓴다: 먼저 뻔한 평균안을 깔고, 어디가 예측 가능한지 표로 쪼갠 뒤, **어디를 깰지는 사용자가 고른다.** 디자인/연출 선택지는 2~5개를 서로 다른 축으로 제시하고 멈춘다. 완성본을 혼자 밀어붙이지 않는다.
- "엣지있게", "대담하게" 같은 형용사 요청은 그대로 실행하지 말고, 위 방식으로 바꿔 제안한다.
- 소통은 한국어, 짧고 구어체로.
