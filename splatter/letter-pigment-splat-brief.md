# Letter Pigment → 가우시안 스플랫 이전 브리프

> 대상: 이 웹 아티팩트를 **가우시안 스플랫 렌더링**으로 다시 만들 코딩 에이전트
> 원본: claude.ai 아티팩트 "Letter Pigment" (three.js 메시 버전, 2026-11-06)
> 관련 레포: `reality404studio/meta-mr-picker` 의 `reference/texture-lab/` (같은 알고리즘의 파이썬·C#·HLSL 기준 구현, PR #1)

---

## 0. 한 줄 요약

**짧은 영상 3개를 "이음매 없는 루프 텍스처(물감)"로 만들고, 3D 입체 글자마다 하나씩 골라 셰이더로 입힌다.**
지금은 글자가 메시(ExtrudeGeometry)라서 UV 없는 표면에 트라이플래너로 텍스처를 읽는다. 스플랫 버전에서는 글자를 스플랫 구름으로 바꾸고, **물감을 스플랫마다 매 프레임 읽어 오는 구조**로 옮기면 된다. 영상 → 물감 파이프라인(1~2절)은 그대로 재사용한다.

## 1. 지금 아티팩트가 하는 일

```
[영상 업로드 ×3 슬롯]
   └─▶ 가운데 정사각 크롭 → 256px 프레임 수집 (실재생 + requestVideoFrameCallback, 0.5배속)
       └─▶ 64px 흑백으로 프레임 유사도 행렬 → 최적 루프 구간 (i, j) 탐색
           └─▶ 크로스페이드 8프레임 → 최대 48프레임으로 솎기
               └─▶ 프레임마다 주기화(이음매 제거, FFT) → 플립북 아틀라스 캔버스
                   └─▶ 2톤 색 추출(k-means k=2) → IndexedDB 저장 (이 브라우저만)
[글자 입력] → Rubik 폰트(500~900) → 글자별 ExtrudeGeometry + 외곽선용 스무스 메시
[글자 선택] → 글자마다 슬롯(1~3)·셰이더(5종) 지정
[렌더] 글자별 ShaderMaterial: 아틀라스 + 현재 프레임 → 트라이플래너 샘플 → 모드별 셰이딩
```

공개 파일: `index.html`, `rubik_500~900.json`(three.js typeface, 라틴 159자), `loop_raw.mp4/.webm`(샘플 물결 512px 크롭), `RUBIK_OFL.txt`.

## 2. 영상 → 물감: 포인트 (그대로 가져갈 것)

각 항목은 **무엇을 / 왜** 순서. 스플랫 버전에서도 바꿀 이유가 없다.

### 2.1 프레임 수집은 "실제 재생"으로
- 일시정지 영상에 `currentTime` 을 바꾸며 `seeked` 후 그리는 방식은 **브라우저에 따라 프레임이 안 바뀐다** (헤드리스 Chromium 에서 전 프레임 동일 → 유사도 0 → 루프 탐색이 망가짐).
- 그래서 영상을 DOM 에 1px 로 붙이고 `play()` 하면서 `requestVideoFrameCallback` 의 `mediaTime` 으로 30fps 칸에 꽂는다. 없으면 rAF + `currentTime`.
- **0.5배속 재생 + 수집 중 3D 렌더 쓰로틀(0.25초에 1번)**. 3D 가 무거우면 디코더가 프레임을 건너뛰고, 건너뛴 칸은 직전 프레임으로 채워져 **똑같은 프레임이 연속**된다.
- 그래서 기준값(아래 `base`) 계산에서 **차이가 0 인 연속 쌍은 제외**한다. 이걸 빼먹으면 base≈0 → 점수 폭주.
- 상한: 6초, 30fps → 최대 180프레임. 크롭은 가운데 정사각 → 256px.

### 2.2 루프 탐색 (Video Textures, Schödl 2000 아이디어)
```
g_k   = 프레임 k 의 64×64 흑백 (luma 0.2126/0.7152/0.0722)
D[i,j] = mean |g_i − g_j|
base  = median( D[k,k+1] , 0 초과만 )
후보 (i, j): 프레임 j−1 다음에 i 로 되돌아감. 길이 L = j−i
   L ∈ [round(1.0·30), round(3.0·30)],  L ≥ max(F+2, 6),  j + max(F,1) ≤ N−1
cost(i,j) = Σ_{t=-1..F} w_t · D[i+t, j+t] / Σ w_t     (t=-1, t=F 는 w=0.5, 나머지 1)
선택     = argmin  cost/base − 0.02·(L/fps)           (품질 같으면 긴 루프)
score    = cost/base                                   (진단값)
```
- **핵심은 "한 점"이 아니라 "크로스페이드로 겹칠 구간 전체"의 유사도를 본다는 것.** 겹치는 동안 잔상이 덜 생기는 쌍을 고른다.
- 점수 해석: 1 ≈ 평소 프레임 전환. 물·불·나뭇잎처럼 불규칙한 장면은 **완벽히 닮은 쌍이 원래 없어서 2~3** 이 정상이고, 크로스페이드가 잔상 없이 녹인다. 샘플 물결: score 2.37, 1.0초 루프.
- 클립이 허용 범위보다 짧으면 가능한 가장 긴 구간으로 강제(forced).

### 2.3 크로스페이드
```
F = min(8, N − j)
t < F :  out_t = src[j+t]·(1−w) + src[i+t]·w,   w = smoothstep((t+0.5)/F)
t ≥ F :  out_t = src[i+t]
```
- 끝(j 근처)에서 시작(i 근처)으로 **녹아드는 방향**. 루프 마지막 프레임 `src[j−1]` 다음에 `out_0 ≈ src[j]` 가 와서 이음매가 자연스럽다.
- 수집 fps 를 10~15 로 낮추면 F 도 3~4 로 줄인다 (12fps 에서 F=8 은 0.67초로 너무 김).

### 2.4 프레임 솎기
- 루프가 48프레임을 넘으면 `idx_t = floor(t·L/48)` 로 고르게 솎고 **재생 fps = 30·48/L** 로 낮춘다. 재생 시간(루프 길이)은 그대로.
- `cols = ceil(√n)`, `rows = ceil(n/cols)`, 칸 256px → 48프레임이면 7×7(1792²).

### 2.5 이음매 없는 타일 = 주기화 (Moisan 2011)
```
v      = 경계 이미지 (왼·오른 열, 위·아래 행의 차이만)
ŝ(q,r) = v̂(q,r) / (2cos(2πq/M) + 2cos(2πr/N) − 4),   ŝ(0,0) = 0
p      = u − s          ← 이것만 남긴다
```
- **무늬는 그대로 두고 가장자리 점프만 저주파로 흡수.** 물·풀·자갈 같은 불규칙 무늬에 특히 잘 맞는다. 측정: 타일 경계 점프 3.5배 → 0.70배 (256px), 사진 5.2 → 0.60 (512px).
- R,G 를 복소 FFT 한 번에 실수/허수로 같이 넣는다 (분모가 실수·대칭이라 섞이지 않음). 프레임당 FFT 2쌍.
- **순서: 크롭 → 크로스페이드 → 주기화 → (2톤).** 2톤으로 먼저 자르면 경계 점프가 계단이 돼서 주기화가 중간 회색을 다시 만든다.
- 이걸 해야 트라이플래너에서 무늬를 반복(`fract`)해도 경계가 안 보인다. 스플랫에서도 똑같이 필요하다.

### 2.6 아틀라스 규칙
- PNG/캔버스는 **행 우선, 왼쪽 위부터**. three.js `CanvasTexture`(flipY=true) 기준 셰이더 좌표:
  ```glsl
  vec2 c   = clamp(fract(uv), vec2(halfTexel), vec2(1.0 - halfTexel));   // halfTexel = 0.5/256
  float col = mod(frame, cols), row = floor(frame / cols);
  vec2 a   = vec2((col + c.x) / cols, 1.0 - (row + 1.0 - c.y) / rows);
  ```
- **밉맵 끄기**(칸끼리 섞임), Linear 필터, Clamp. 반복은 `fract` 가 한다. 반 텍셀 클램프로 옆 칸 번짐 방지.
- 현재 프레임 = `floor(T·fps) mod frames`. **슬롯마다** fps·frames 가 다르므로 프레임 번호는 슬롯 단위로 계산해서 그 슬롯을 쓰는 글자에 넣는다.

### 2.7 2톤 색 추출 (앱의 결정된 룩용)
- 아틀라스에서 약 6000픽셀 샘플 → k-means(k=2, 10회, 초기값 밝기 20%/80% 지점) → 밝은 쪽 = light, 어두운 쪽 = shadow.
- 경계값 `th = (luma(light) + luma(shadow)) / 2` (sRGB 값 기준). 셰이더에서 `step(th, luma(sRGB 텍셀))` 로 무늬를 두 톤으로 가른다.

### 2.8 저장
- IndexedDB `letter-pigment` / store `slots` / key `slot0..2` → `{ blob: 아틀라스 PNG, meta, name }`.
- `meta = { cols, rows, frames, fps, tile, loopSec, score, tones:{light, shadow, th} }`.
- localStorage: `lp.text`, `lp.assign`(글자별 슬롯), `lp.modes`(글자별 셰이더). 전부 try/catch, 실패해도 페이지는 돈다.
- 첫 방문이면 슬롯1 에 샘플 물결을 자동으로 채운다.

## 3. 셰이더화: 포인트

### 3.1 색 공간
- 아틀라스 텍스처는 `NoColorSpace` 로 올리고 **셰이더에서 직접 `pow(c, 2.2)` 로 선형화**, 마지막에 `#include <colorspace_fragment>` 로 sRGB 출력. 브라우저마다 VideoTexture/CanvasTexture 의 sRGB 자동 디코드가 달라서 일관성 위해 수동으로 했다.
- 2톤 경계 판정(`th`)만은 **sRGB 값**으로 한다 (k-means 를 sRGB 에서 했으므로).

### 3.2 트라이플래너 (UV 없는 표면)
```glsl
vec3 w = pow(abs(n), vec3(4.0)); w /= (w.x + w.y + w.z);
col = cell(p.zy*scale + 0.13)*w.x + cell(p.xz*scale + 0.37)*w.y + cell(p.xy*scale + 0.71)*w.z;
```
- **오브젝트 공간** 위치·노멀을 넘기면 무늬가 글자에 붙어서 같이 돈다 (기본).
- **월드 공간**을 넘기면 무늬가 공간에 고정되고 글자가 그 속을 지나간다 → Caustic 모드.
- 축마다 다른 오프셋(0.13/0.37/0.71): 세 투영면의 무늬가 같은 자리에서 겹쳐 보이지 않게.
- 글자는 각자 **자기 중심을 원점**으로 지오메트리를 옮겨 둔다 (회전·둥실 피벗 + 트라이플래너 기준점).

### 3.3 셰이더 5종 (글자별 선택)
`tex` = 선형화한 텍셀, `h = luma(tex)`, `d = max(dot(N, L), 0)`, `L = normalize(0.45, 0.8, 0.55)`, `uInt` = 강도.

| 모드 | 식 | 의도 |
| --- | --- | --- |
| 0 그대로 | `tex·(0.32 + 0.85d)·uInt + spec(40)·0.2` | 무늬가 어떻게 감기는지 확인용 |
| 1 2톤 셀 | `tone = mix(shadow, light, step(th, luma(texSRGB)))`, `col = tone·mix(0.42, 1.0, step(0.35, d))` + 남색 외곽선 `#2E3350` | **앱에서 결정된 룩.** 무늬는 두 톤으로 남기고, 빛은 밝은 면/그림자 두 단계만 |
| 2 Glint | `g = smoothstep(0.6, 0.68, h)`, `core = smoothstep(0.68, 1, h)`, `col = 하늘색·(1.6g + 2.5core) + 아주 어두운 몸통 + 프레넬 림 0.12` | 반짝임만 발광. **투과형 글래스(검정=투명)에서 가장 잘 살아남는 구조** |
| 3 Chrome | 밝기를 높이로 보고 노멀 흔들기(강도 2.2) → `reflect` → 절차적 환경(하늘 그라데이션·수평선·소프트박스 줄·태양) × 프레넬(0.55 + 0.45·(1−N·V)^5) + `h^4·1.2` | 표면 위로 물결이 흐르는 수은 느낌 |
| 4 Caustic | 월드 트라이플래너, `어두운 무광 몸통 + 하늘색·h^3·4·(0.35 + 0.65d)` | 물에 반사된 빛이 글자 위를 지나감 |

- 슬롯이 비어 있는 글자는 텍셀 대신 회색 0.42.
- 노멀 흔들기(메시 버전)는 화면 미분(`dFdx/dFdy`)으로 한다:
  ```glsl
  vec3 dpx = dFdx(pos), dpy = dFdy(pos); float dhx = dFdx(h)*k, dhy = dFdy(h)*k;
  vec3 r1 = cross(dpy, n), r2 = cross(n, dpx); float det = dot(dpx, r1);
  N' = normalize(abs(det)*n − sign(det)*(dhx*r1 + dhy*r2));
  ```
  → **스플랫에는 화면 미분이 없으니 텍스처 공간 유한 차분으로 바꿔야 한다** (6절).

### 3.4 외곽선 (2톤 셀 전용)
- 뒤집힌 껍데기(inverted hull): 같은 글자를 `BackSide` 로 한 번 더 그리고 정점을 노멀 방향으로 `0.018·size` 밀어 남색으로 칠한다.
- ExtrudeGeometry 노멀은 모서리에서 갈라져 있어서 그대로 밀면 **모서리가 찢어진다** → 노멀/UV 를 지운 복사본에 `mergeVertices(1e-4)` + `computeVertexNormals()` 로 **스무스 노멀 전용 지오메트리**를 따로 만든다.

### 3.5 글자별 머티리얼 구조
- 공유 uniform 객체(`uScale`, `uInt`, `uTime`, `uOutline`)는 **같은 객체 참조**로 모든 머티리얼에 펼쳐 넣는다 (슬라이더 하나로 전체 갱신).
- 글자 고유: `uMode`, `uAtlas`, `uLayout(cols, rows, halfTexel, 0)`, `uFrame`, `uHas`, `uLight`, `uShadow`, `uTh`.
- 선택(여러 글자) → 슬롯/셰이더 버튼이 **선택한 글자에만** 적용. 아무것도 안 고르면 전체.

## 4. 글자 지오메트리

- 폰트: **Rubik** (Google Fonts, OFL), 굵기 500/600/700/800/900. `@fontsource/rubik` woff → three.js `TTFLoader` 로 typeface JSON 변환, 라틴(0x20–0x7E, 0xC0–0xFF) 159자만. 한글 없음 → 입력하면 경고 후 제외.
- `font.generateShapes(ch, size)` → `ExtrudeGeometry({ depth: 0.32·size, curveSegments: 10, bevelThickness: 0.024·size, bevelSize: 0.024·size·0.7, bevelSegments: 4 })`.
- 배치: 글자 advance = `glyph.ha / resolution · size` + 자간 `gap·size`. 줄 전체를 가운데 정렬, 세로는 `0.36·size` 를 중심으로.
- 애니메이션: 글자마다 `rotation.y = sin(0.5T + φ)·0.55`, `y += sin(1.3T + φ)·0.04·size`, φ = 글자 순번·0.9.
- 카메라: 줄 폭이 화면 가로의 약 80% 를 차지하도록 거리 맞춤 (`거리 = 폭·0.62 / tan(가로FOV/2)`).
- 조절: 크기 0.5–2, 굵기 500–900, 두께 0.05–0.9, 모서리 0–0.06, 자간 −0.1–0.4, 무늬 크기 0.2–3, 강도 0.2–2.

## 6. 가우시안 스플랫으로 옮길 때 (제안)

### 6.1 무엇이 바뀌나

| 메시 버전 | 스플랫 버전 |
| --- | --- |
| ExtrudeGeometry 표면 | 그 표면에서 **면적 비례로 점을 샘플링**한 스플랫 구름 (글자당 하나의 스플랫 묶음) |
| 프래그먼트마다 트라이플래너 샘플 | **스플랫마다** 중심 위치 + 저장해 둔 노멀로 트라이플래너 샘플 (스플랫 셰이더/모디파이어에서 매 프레임) |
| 버텍스 노멀 | 스플랫별 노멀을 **따로 저장** (샘플링할 때 메시 노멀에서 가져옴). 트라이플래너·셀 조명·크롬 반사 모두 필요 |
| 화면 미분 범프 | 아틀라스에서 **텍스처 공간 유한 차분**: `h(uv ± ε)` 로 기울기 → 노멀 흔들기 |
| inverted hull 외곽선 | 노멀 방향으로 살짝 바깥·뒤쪽에 놓은 **남색 스플랫 한 겹**(작은 불투명), 또는 깊이 기반 화면 외곽선 |
| 메시 색 = 셰이더 결과 | 스플랫 색(+불투명도) = 셰이더 결과. Glint 는 **불투명도까지 h 로 조절**하면 "반짝이는 입자로 된 글자"가 되어 스플랫다운 룩이 나온다 |

### 6.2 스플랫 모양
- 표면 스플랫은 **납작하게**: 접평면 두 축 = 샘플 간격 정도, 노멀 축 = 그 1/10 이하. 회전은 노멀에서 쿼터니언으로.
- 밀도: 측정한 값은 없다. 출발점으로 글자 높이당 150~250 간격(글자당 수만 개)을 추정하고, 무늬 크기 슬라이더와 함께 실제로 보며 튜닝한다.
- 옆면·베벨도 샘플링해야 두께감이 남는다. 앞면만 하면 종이 글자가 된다.

### 6.3 시간축
- **스플랫 위치는 고정, 색만 매 프레임 바뀐다** → 정렬(sort)은 카메라가 움직일 때만 필요. 색을 CPU 에서 프레임마다 굽는 방식(스플랫 수 × 프레임 수)은 메모리가 터지니 **GPU 에서 아틀라스를 읽는 방식**을 권한다.
- 글자별 회전·둥실은 글자 단위 변환(스플랫 묶음의 transform)으로. 글자 내부 스플랫 순서는 프레임 간 안정적으로 유지.

### 6.4 모드별 메모
- **2톤 셀**: 스플랫별 노멀로 `step(0.35, N·L)`, 무늬는 `step(th, luma)`. 셀 경계가 스플랫 크기만큼 부드러워지니 스플랫을 작게.
- **Glint**: `h < 0.6` 인 스플랫은 불투명도를 0 근처로 → 투과형 글래스 미리보기(검정=투명)와 궁합이 가장 좋다.
- **Chrome**: 스플랫별 시선 방향(카메라 − 중심)으로 `reflect`. 범프는 6.1 의 유한 차분.
- **Caustic**: 월드 중심으로 트라이플래너. 글자가 회전하면 무늬가 스플랫 위를 흐른다.

### 6.5 라이브러리 후보
- **Spark** (World Labs, three.js 기반 스플랫 렌더러, sparkjs.dev): `PackedSplats.pushSplat(center, scales, quaternion, opacity, color)` 로 절차적 스플랫 생성, `textSplats` 헬퍼, `dyno` 라는 GPU 프로그램으로 스플랫을 프레임마다 수정하는 구조가 있다. 2.0 이 나와 있다. **모디파이어에서 텍스처 샘플이 되는지, 스플랫별 사용자 속성(노멀)을 어떻게 싣는지는 문서로 직접 확인할 것.** 안 되면 노멀을 별도 데이터 텍스처에 인덱스로 넣는 방식.
- 직접 구현: 인스턴스드 쿼드 + 3D 공분산 → 2D 투영 + 뒤→앞 정렬. 스플랫 수가 수십만 이하면 충분히 가능.

### 6.6 완료 기준
1. 영상 3개 → 물감 3개 (1~2절 파이프라인 그대로, 점수·고유 프레임 수 같은 진단값 노출)
2. 텍스트 입력 → 글자별 스플랫 묶음, 크기·굵기·두께 조절 시 다시 샘플링
3. 글자 선택 → 슬롯·셰이더가 선택한 글자에만
4. 5개 모드 중 최소 **2톤 셀**과 **Glint** 가 스플랫에서 동작 (셀은 앱 룩, Glint 는 스플랫 강점)
5. 무늬가 루프 재생되고, 타일 경계·루프 이음매가 안 보임
6. 폰 브라우저에서 30fps 이상 (스플랫 수 상한을 슬라이더나 자동으로)

## 7. 지키거나 하지 말 것

- 앱 룩은 **2톤 셀로 결정**돼 있다. Glint·Chrome·Caustic 은 탐색 결과일 뿐, 앱에 채택할지는 사람이 정한다.
- 원본 영상 전체 프레임을 저장하지 않는다 (크롭만). 원본 영상을 git 에 넣지 않는다.
- 한글은 지금 폰트에 없다. 넣으려면 한글 굵은 폰트(예: Black Han Sans, Noto Sans KR Black)를 상용 2,350자만 따로 변환해야 하고 파일이 수 MB 가 된다. 사람에게 먼저 묻는다.
- 아티팩트 환경 제약(이 웹 버전을 다시 아티팩트로 낼 경우): 외부 스크립트는 cdnjs/jsdelivr/unpkg 만, 같이 올린 파일은 상대경로 fetch 가능, 파일 저장은 `downloads` 기능을 통해서만.
